# Core Resume

Core Resume (called Overreactive Resume until 2026-10-20) is a downstream fork of [Reactive Resume](https://github.com/reactive-resume/reactive-resume). It follows upstream closely and adds what its maintainer needs for a self-hosted job search. Changes that suit everyone may be offered upstream; the rest stay here.

This file is the fork's patch list: every change that is not in upstream, and where it stands.

## Branches

| Branch                      | What it holds                                                                                                                      |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `main`                      | Core Resume: upstream plus the fork's changes. The default branch and what gets deployed. Changes land only through pull requests. |
| `upstream`                  | An exact mirror of `reactive-resume/reactive-resume:main`. It only fast-forwards and never carries fork commits.                   |
| `feat/*`, `fix/*`, `docs/*` | Work in progress, cut from `main` and merged back into `main` with a merge commit.                                                 |

A change offered upstream gets its own branch cut from `upstream`, so the upstream pull request carries only that change.

## Syncing with upstream

1. Fast-forward `upstream`: `git fetch upstream && git push origin upstream/main:refs/heads/upstream`.
2. Open a pull request from `upstream` into `main` titled `Merge upstream <version or date>`, resolve any conflicts there, and merge it with a merge commit. `main` is never rebased or force-pushed.
3. Sync at upstream release tags by default; take an untagged upstream commit only when a specific fix is needed sooner.
4. When upstream merges a change that started here, resolve conflicts in favor of upstream's version and mark it **Upstream** below.
5. Conflicts in `apps/web/locales/*.po`: take upstream's side, then run `pnpm lingui:extract`, which rebuilds the catalogs and refills en-US and en-GB (see **English catalogs** below).

## Keeping the fork cheap to maintain

- Prefer additive changes: new files and settings rather than edits spread through upstream code.
- Don't reformat or rename upstream code. Internal package names (`@reactive-resume/*`), the database and environment variable names stay as upstream has them.
- Strings added here ship in English; the fork may fill in translations that upstream's Crowdin doesn't cover.
- Upstream's GitHub Actions workflows stay disabled on this repository.

| **Knowledge curation.** Career → Knowledge → Curate, built in steps. Budget meter (also in AI limits): shared switched-on facts and usable stories in the JSON characters the action budgets use, the Coach's per-message counts, and an estimated token count (characters / 4, posting and documents included) against the default connection's context window from models.dev, or one set by hand per connection (column `ai_providers.context_tokens`) for models it doesn't list. Groups: `career_fact.group` holds a path such as `experience/acme`; Curate switches a group and its subgroups on or off, and facts added later start as the group was last switched (table `career_fact_group`). Facts get a group filter and a Group action. API and MCP: `GET /career/facts/groups`, `POST /career/facts/groups/status` (group in the body, since paths contain slashes), `PATCH /career/facts` for bulk switching or regrouping, `GET /career/facts?group=`. Private groups (`career_fact_group.private`) never reach the AI, whatever their facts' switches, unless an application includes them; each application's details get Knowledge for this job, which includes or leaves out groups (facts too, through the API) without copying anything (table `career_fact_override`, `GET`/`PUT /career/overrides`, `DELETE /career/overrides/{id}`, `PUT /career/facts/groups` for privacy). Archive: status `archived` keeps a fact, hidden and never sent, restorable. Duplicates: Curate lists exact (normalized text) and near (stemmed-word overlap) duplicates within one scope; Remove copies folds application copies of shared facts into them (adding an include override where the shared fact wouldn't reach that application), and saving a new copy returns the shared fact; merge moves stories, saved items and overrides to the fact kept and archives the other (keeping an application's fact over a shared one makes it shared) (`GET /career/facts/duplicates`, `POST /career/facts/duplicates/clean`, `POST /career/facts/{id}/merge`). Curate also lists stories the AI can't use, with why, and confirms a story after a correction in one step. Knowledge review: on demand, removes application copies first, then asks the default AI connection, in up to eight requests within the action budgets and time limit, to flag contradictions, superseded figures and unsupported claims among the shared facts that reach the AI (never private, switched-off or archived ones); the user archives, keeps the newer one, corrects or dismisses each (table `career_review`, `GET`/`POST /career/knowledge/review`, `PATCH /career/knowledge/review/{id}`). One rule, `reachesAi`, decides for the server context, Coach search, story saving, the Coach's Used chips and the budget meter.
